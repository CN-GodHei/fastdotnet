# 事件总线

Fastdotnet 事件总线是插件间通信的核心基础设施，支持 **强类型**（进程内模块通信）和 **弱类型**（跨插件通信）两种模式。

## 概述

```
┌─────────────────────────────────────────────────────────────────┐
│                      Fastdotnet 事件总线                          │
│                                                                   │
│  强类型模式                  弱类型模式                            │
│  ──────────                  ──────────                           │
│  进程内模块通信              跨插件通信                            │
│  编译期类型安全              JSON 序列化，零 DLL 依赖              │
│  IEventHandler<T>            Func<object, Task>                   │
│  按 CLR 类型路由             按 eventKey 路由                      │
│  PublishAsync<T>(event)      PublishAsync(eventKey, data)         │
└─────────────────────────────────────────────────────────────────┘
```

- **强类型**：适合插件内部模块解耦，编译期检查类型
- **弱类型**：适合跨插件通信，插件 A 不依赖插件 B 的 DLL

---

## 事件目录

Fastdotnet 提供了类似 Swagger 的事件目录 UI，启动后访问：

```
http://localhost:18889/api/eventcatalog/ui
```

![事件目录](public/eventcatalog-ui.png)

事件目录展示所有已加载插件的可订阅事件，包含：
- **完整 eventKey**：`{pluginId}.{eventName}`（如 `11365281228127823.payment.completed`）
- **插件名称**：发布该事件的插件
- **Payload Schema**：事件数据的属性及类型
- **事件分组**：按业务领域分类

这是跨插件通信时查找 eventKey 的主要途径。

## 快速开始

### 1. 注册事件总线（主框架）

在 `Program.cs` 中添加一行：

```csharp
builder.Services.AddEventBus();
```

并在 `app.Build()` 后初始化：

```csharp
await app.Services.InitializeEventBusAsync();
```

### 2. 定义事件（支付插件）

在插件项目中创建事件类，使用 `[EventContract]` 特性声明：

```csharp
using Fastdotnet.Plugin.Contracts.Events;

namespace Fastdotnet.Pay.Events;

/// <summary>
/// 支付完成事件
/// </summary>
[EventContract("payment.completed", Description = "支付完成", Group = "Payment")]
public class PaymentCompletedEvent : DomainEvent
{
    public string OrderId { get; set; } = string.Empty;
    public string TransactionNo { get; set; } = string.Empty;
    public decimal PaidAmount { get; set; }
    public DateTime PaidAt { get; set; }
    public string PaymentChannel { get; set; } = string.Empty;
}
```

> - `EventContract` 的第一个参数是**事件短名**（如 `payment.completed`）
> - 框架在插件加载时自动拼接为完整 eventKey：`{pluginId}.payment.completed`
> - 事件的完整 key 在 `/api/eventcatalog/ui` 中可见

### 3. 发布事件

**强类型发布**（插件内部）：

```csharp
public class PaymentController
{
    private readonly IEventBus _eventBus;

    public PaymentController(IEventBus eventBus)
    {
        _eventBus = eventBus;
    }

    public async Task OnPaymentSuccess(string orderId, decimal amount)
    {
        await _eventBus.PublishAsync(new PaymentCompletedEvent
        {
            OrderId = orderId,
            PaidAmount = amount,
            TransactionNo = $"TXN_{Guid.NewGuid():N}",
            PaidAt = DateTime.Now,
            PaymentChannel = "Alipay"
        });
    }
}
```

**弱类型发布**（跨插件通信）：

从事件目录 `/api/eventcatalog/ui` 查到支付插件的完整 eventKey 后：

```csharp
// 方式一：硬编码完整 eventKey（从事件目录查到的）
const string eventKey = "11365281228127823.payment.completed";

await _eventBus.PublishAsync(eventKey, new
{
    OrderId = orderId,
    PaidAmount = amount,
    TransactionNo = $"TXN_{Guid.NewGuid():N}",
    PaidAt = DateTime.Now,
    PaymentChannel = "Alipay"
});
```

或通过 `IEventRegistry` 动态查询：

```csharp
var def = _eventRegistry.GetAll()
    .FirstOrDefault(d => d.EventName == "payment.completed");

if (def != null)
{
    await _eventBus.PublishAsync(def.EventKey, eventData);
}
```

### 4. 订阅事件

**强类型订阅**（Handler 类）：

```csharp
public class OrderPaidHandler : IEventHandler<PaymentCompletedEvent>
{
    private readonly ILogger<OrderPaidHandler> _logger;

    public OrderPaidHandler(ILogger<OrderPaidHandler> logger)
    {
        _logger = logger;
    }

    public async Task HandleAsync(PaymentCompletedEvent @event, CancellationToken ct)
    {
        _logger.LogInformation("收到支付完成：订单={OrderId}, 金额={Amount}",
            @event.OrderId, @event.PaidAmount);
    }
}
```

**弱类型订阅**（Lambda，跨插件）：

```csharp
// 精确订阅某个插件的事件
var sub = _eventBus.Subscribe("11365281228127823.payment.completed", async data =>
{
    var json = (System.Text.Json.JsonElement)data;
    var orderId = json.GetProperty("orderId").GetString();
    // 处理事件...
});

// 通配符匹配所有插件的同名事件
var sub = _eventBus.Subscribe("*.payment.completed", async data =>
{
    // 任意插件发布 payment.completed 都会触发
});

// 取消订阅
sub.Dispose();
```

## eventKey 命名规范

```
格式：{pluginId}.{eventName}

示例：
  11365281228127823.payment.completed      ← 支付插件发布的支付完成事件
  11365281228127823.payment.requested      ← 支付插件发布的支付请求事件
  12876371399345157.order.created          ← 电商插件发布的订单创建事件
```

**通配符规则**：

| 模式 | 匹配范围 |
|------|---------|
| `11365281228127823.payment.*` | 支付插件的所有 payment 事件 |
| `*.payment.completed` | 任意插件的 payment.completed 事件 |

## EventContract 特性参考

```csharp
[AttributeUsage(AttributeTargets.Class)]
public class EventContractAttribute : Attribute
{
    /// <summary>事件短名（不含插件ID），如 "payment.completed"</summary>
    public string Name { get; }

    /// <summary>事件描述（显示在事件目录中）</summary>
    public string Description { get; set; }

    /// <summary>事件分组，如 "Payment"、"Order"、"System"</summary>
    public string Group { get; set; } = "General";

    /// <summary>事件方向：Published（发布）或 Subscribed（订阅）</summary>
    public EventDirection Direction { get; set; } = EventDirection.Published;
}
```

## IEventBus API 参考

```csharp
public interface IEventBus
{
    // ===== 强类型 =====
    Task PublishAsync<TEvent>(TEvent @event, CancellationToken ct = default)
        where TEvent : class;
    IDisposable Subscribe<TEvent>(IEventHandler<TEvent> handler)
        where TEvent : class;
    void Unsubscribe<TEvent>(IEventHandler<TEvent> handler)
        where TEvent : class;

    // ===== 弱类型（跨插件）=====
    Task PublishAsync(string eventKey, object eventData, CancellationToken ct = default);
    IDisposable Subscribe(string eventKey, Func<object, Task> handler);
    void UnsubscribeAll(string eventKey);
}
```

## 最佳实践

### ✅ 推荐

- 事件类命名用**过去时态**：`PaymentCompletedEvent`、`OrderCreatedEvent`
- 事件只包含必要数据，复杂逻辑放 Handler 中
- 跨插件通信优先使用**弱类型 API**，不依赖对方 DLL
- 发布前先查 `/api/eventcatalog/ui` 确认完整 eventKey
- 返回的 `IDisposable` 用完后及时释放或随插件卸载释放

### ❌ 不推荐

- 在事件中包含复杂对象引用或循环引用
- 强类型跨插件通信（会导致 DLL 依赖传染）
- 事件间互相触发形成死循环
- 一个 Handler 处理多个不相关的事件

### Handler 设计原则

```csharp
// ✅ 单一职责
public class SendEmailOnPaymentCompleted : IEventHandler<PaymentCompletedEvent> { }

public class UpdateInventoryOnPaymentCompleted : IEventHandler<PaymentCompletedEvent> { }

// ❌ 违反单一职责
public class GodHandler : IEventHandler<PaymentCompletedEvent>,
                          IEventHandler<OrderCreatedEvent>,
                          IEventHandler<UserRegisteredEvent> { }
```

## 架构关系

事件总线与 Notification 推送系统是两个独立的基础设施：

| | EventBus（事件总线） | Notification（推送系统） |
|---|---|---|
| 目的 | 插件间进程内通信 | 框架对外推送 |
| 路由 | `/api/eventcatalog/*` | `/_events/*` |
| 协议 | AsyncAPI 2.6 | AsyncAPI 2.6 + CloudEvents |
| 事件基类 | `EventBase` / `DomainEvent` | `IFastdotnetEvent` |
| eventKey 格式 | `{pluginId}.{eventName}` | `com.fastdotnet.order.paid.v1` |
| 持久化 | 不需要（内存级） | Outbox 事务落库 |

两者共享 AsyncAPI 2.6 标准，但通过不同路由和数据源独立运行。
