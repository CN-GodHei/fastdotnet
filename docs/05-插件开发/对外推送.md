# 框架对外推送

Fastdotnet 推送系统是框架底层的事件推送基础设施，负责将业务事件可靠投递到**外部系统**（前端页面、第三方 Webhook）。

## 概述

```
                              推送系统架构
┌──────────────────────────────────────────────────────────────────┐
│                                                                   │
│  业务代码 / 插件                                                   │
│    │ IEventPublisher.PublishAsync(evt)                            │
│    │ db.FlushOutboxAsync(context)  ← 事务内统一落库                 │
│    ▼                                                              │
│  ┌──────────────────────────────────────┐                         │
│  │  OutboxDispatcher (后台调度)          │                         │
│  │  ├ Channel 内存信号 (毫秒级)           │                         │
│  │  ├ 定时轮询 (5s 兜底)                 │                         │
│  │  └ SqlSugar 乐观锁 (多节点分布式抢占)  │                         │
│  │         │                            │                         │
│  │         ▼                            │                         │
│  │  EventRouter                         │                         │
│  │   ├ 精确匹配 + 通配符                  │                         │
│  │   ├ Subscribe / Unsubscribe          │                         │
│  │         │                            │                         │
│  │         ├── SignalRSubscriber → 前端  │                         │
│  │         └── WebhookSubscriber → 第三方 │                         │
│  └──────────────────────────────────────┘                         │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

**核心特性**：事务内落库 → 分布式抢占调度 → SignalR 实时推送 / Webhook 外部回调 → 指数退避重试 → 死信归仓。

与 [事件总线](./事件总线.md) 的区别：

| | 推送系统 | 事件总线 |
|---|---|---|
| 目的 | 框架 → 外部系统 | 插件 ↔ 插件（内部） |
| 通道 | SignalR + Webhook | 进程内内存 |
| 持久化 | ✅ Outbox 事务落库 | ❌ 不需要 |
| 可靠投递 | ✅ 重试 + 死信 | ❌ 即发即忘 |
| 协议 | CloudEvents 1.0 | 无标准 |
| 端点 | `/_events/spec` + `/_events/ui` | `/api/eventcatalog/*` |
| 使用场景 | 订单通知、状态推送、第三方回调 | 支付插件通知电商插件 |

## 快速开始

### 1. 注册推送服务

在 `Program.cs` 中：

```csharp
using Fastdotnet.Core.Notification;

builder.Services.AddFastdotnetNotification(options =>
{
    options.DispatcherOptions.PollingInterval = 5;    // 轮询间隔（秒）
    options.DispatcherOptions.BatchSize = 50;          // 批量大小
    options.DispatcherOptions.MaxRetryCount = 10;      // 最大重试次数
});
```

### 2. 定义推送事件

```csharp
using Fastdotnet.Core.Notification;

/// <summary>
/// 订单创建事件（推送到前端/外部系统）
/// </summary>
[EventContract("com.fastdotnet.order.created.v1", Description = "订单创建事件")]
public record OrderCreatedEvent(
    string OrderId,
    decimal Amount,
    string CustomerId
) : IFastdotnetEvent;
```

> **命名规范**：采用反向域名风格 `com.{项目}.{模块}.{事件}.{版本号}`
> 如 `com.fastdotnet.order.paid.v1`

### 3. 发布事件（事务内）

```csharp
public class OrderService
{
    private readonly ISqlSugarClient _db;
    private readonly IEventPublisher _publisher;
    private readonly EventContext _eventContext;

    public OrderService(ISqlSugarClient db, IEventPublisher publisher, EventContext eventContext)
    {
        _db = db;
        _publisher = publisher;
        _eventContext = eventContext;
    }

    public async Task CreateOrderAsync(OrderDto dto)
    {
        await _db.Ado.UseTranAsync(async () =>
        {
            // 1. 业务写入
            var entity = dto.ToEntity();
            await _db.Insertable(entity).ExecuteCommandAsync();

            // 2. 发布事件（延迟收集，不立即操作 DB）
            await _publisher.PublishAsync(new OrderCreatedEvent(
                entity.Id, entity.Amount, entity.UserId));

            // 3. 事务内统一落库 SysOutbox
            await _db.FlushOutboxAsync(_eventContext);
        });
    }
}
```

启动后访问：

```
http://localhost:18889/_events/ui
```

**`/_events/spec`** 返回 AsyncAPI 2.6 JSON 规范，供外部系统集成使用。

**`/_events/ui`** 提供可视化浏览页面，展示所有已注册的推送事件及 Payload Schema。

## 投递通道

### SignalR（前端实时推送）

前端通过 SignalR 连接 `/universalhub`，订阅事件后实时接收推送：

```javascript
const connection = new signalR.HubConnectionBuilder()
    .withUrl("http://localhost:18889/universalhub")
    .build();

connection.on("com.fastdotnet.order.created.v1", (event) => {
    console.log("收到订单创建通知", event);
});

connection.start();
```

### Webhook（第三方 HTTP 回调）

外部系统提供回调 URL，推送系统自动 POST 事件数据：

```
POST https://third-party.com/api/callback
Content-Type: application/cloudevents+json
X-Fastdotnet-Signature: t=1718000000,v1=abc123...

{
  "specversion": "1.0",
  "type": "com.fastdotnet.order.paid.v1",
  "source": "fastdotnet",
  "id": "evt_abc123",
  "data": {
    "orderId": "ORD_001",
    "amount": 99.90
  }
}
```

**安全签名**：

```
签名串 = HMAC-SHA256(Timestamp + "." + EventId, TenantSecretKey)
```

第三方系统可以用相同的算法验证请求来源。

## 可靠投递保障

### Outbox 模式

```
业务事务提交                          后台调度
──────────                          ────────
INSERT Order  ┐                     Channel 信号唤醒
INSERT SysOutbox ┘  ← 同一事务        ↓
                                    UPDATE SysOutbox SET Status=Processing (乐观锁抢占)
                                          │
                                          ├── 成功 → Status=Published
                                          └── 失败 → 指数退避重试
                                                      │
                                                      ├── 重试 < 10次 → 更新 NextAttemptTime
                                                      └── 重试 ≥ 10次 → 移入死信表
```

### 重试策略

| 重试次数 | 延迟 |
|---------|------|
| 1 | 1 秒 |
| 2 | 2 秒 |
| 3 | 4 秒 |
| ... | 指数退避 |
| ≥ 10 | 移入死信表 |

### 死信处理

超过最大重试次数的事件自动移入 `sys_dead_letter` 表。可通过管理接口一键重放：

```
POST /api/v1/infra/notification/dead-letter/replay
{
  "tenantId": "tenant-001",
  "startTime": "2026-06-01T00:00:00Z"
}
```

## EventContract 特性参考

```csharp
[AttributeUsage(AttributeTargets.Class)]
public class EventContractAttribute : Attribute
{
    /// <summary>事件类型（反向域名格式），如 "com.fastdotnet.order.paid.v1"</summary>
    public string EventType { get; }

    /// <summary>事件描述</summary>
    public string? Description { get; set; }
}
```

注：此特性与 EventBus 中的 `EventContractAttribute` 是不同命名空间的独立特性：
- `Fastdotnet.Core.Notification.EventContractAttribute` — 对外推送
- `Fastdotnet.Plugin.Contracts.Events.EventContractAttribute` — 插件间 EventBus

## 配置选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `DispatcherOptions.PollingInterval` | 5 | 定时轮询间隔（秒） |
| `DispatcherOptions.BatchSize` | 50 | 每次抢占的最大消息数 |
| `DispatcherOptions.LockDurationSeconds` | 30 | 分布式锁持有时间（秒） |
| `DispatcherOptions.MaxRetryCount` | 10 | 最大重试次数，超过移入死信 |

## 数据表结构

### sys_outbox（发件箱）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | char(36) | 事件唯一 ID |
| `tenant_id` | varchar(50) | 租户 ID |
| `event_type` | varchar(150) | 事件类型标识 |
| `payload` | text/json | CloudEvents 标准载荷 |
| `status` | int | 0-Pending, 1-Processing, 2-Published, 3-Failed |
| `retry_count` | int | 重试次数 |
| `next_attempt_time` | datetime | 下次重试时间 |
| `lock_id` | char(36) | 抢占节点实例 ID |
| `lock_expired_time` | datetime | 锁过期时间 |

### sys_dead_letter（死信表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | char(36) | 继承原事件 ID |
| `tenant_id` | varchar(50) | 租户 ID |
| `event_type` | varchar(150) | 事件类型 |
| `payload` | text | 完整载荷 |
| `error_message` | text | 最后失败原因 |
| `failed_at` | datetime | 归入死信时间 |

## 最佳实践

### ✅ 推荐

- 事件发布放在**数据库事务内**，用 `FlushOutboxAsync` 统一落库
- 事件命名用**反向域名 + 版本号**：`com.fastdotnet.order.created.v1`
- 实现 `IFastdotnetEvent` 接口（推荐用 `record` 类型）
- Webhook 接收方验证 `X-Fastdotnet-Signature` 签名
- 定期检查死信表，通过 replay API 重放失败事件

### ❌ 不推荐

- 在事务外单独调用 `PublishAsync`（可能导致数据不一致）
- 事件 Payload 中包含敏感信息（明文传输到外部）
- Webhook URL 使用 HTTP（应使用 HTTPS）
- 忽略死信表中的事件（可能导致业务数据丢失）
